## Phase 3: 任务分解 + 进度锚点

### 步骤

1. **解析方案**为原子子任务，每个子任务满足：
   - 单一职责：只做一件事
   - 可验证：有明确的完成条件
   - 可估计：能给出大致耗时级别

2. **为每个子任务打标签**：

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 唯一编号 | T1, T2 |
| phase | 所属阶段 | env_check, file_edit, config, run, verify |
| description | 任务描述 | 检查并激活 conda 环境 |
| estimate | 预估耗时 | S(<5min), M(5-15min), L(15-60min), XL(>1h) |
| weight | 进度权重 (百分比) | 10, 20 |
| milestones | 内部里程碑（长任务用） | ["pip install 完成", "import 验证通过"] |
| completion | 完成条件 | python -c 'import torch; print(torch.cuda.is_available())' 返回 True |

### 进度锚点规则

- **短任务**（S/M）：不拆内部里程碑，完成即算 100%
- **长任务**（L/XL）：必须拆出 2-4 个内部里程碑作为进度锚点
- **进度权重**：按预估耗时比例分配，总合 = 100%

### 复杂度评估（初步）

| 子任务数 | 复杂度评级 | 建议 |
|----------|-----------|------|
| <= 5 | 简单 | 直接执行 |
| 6-15 | 中等 | 正常执行 |
| > 15 | **复杂** | **提示用户：建议拆成多个独立 Plan 执行** |
| 含 XL 任务 | — | 强制拆成 M 级子任务，不允许 XL 原样进入 Todo List |
