## Phase 2: 方案逻辑检查

在动手拆分任务之前，先判断方案的逻辑是否站得住。

### 7 项逻辑检查

| # | 检查项 | 核心问题 | 判定 |
|---|--------|----------|------|
| 1 | **目标对齐** | 方案是否直接解决用户提出的核心目标？ | FAIL：方案与目标无直接因果关系 |
| 2 | **因果链合理性** | 从改动到最终结果的推理链条每一步是否站得住？ | FAIL：跳跃式推理，缺失关键中间步骤 |
| 3 | **假设显式化** | 方案依赖哪些隐式假设？这些假设是否成立？ | FAIL：关键假设不成立或不可验证 |
| 4 | **竞品方案** | 有没有更简单/更便宜/更快的做法？（同成本量级内） | WARN：有更优方案但未评估 |
| 5 | **副作用分析** | 这个改动还会影响系统的哪些其他部分？ | WARN：明显副作用未评估 |
| 6 | **完整性缺口** | 方案漏掉了什么必要步骤？ | FAIL：缺必要条件步骤 |
| 7 | **可执行性** | 方案在当前资源约束下能不能落地？ | FAIL：资源需求远超实际可用 |

**竞品方案的边界**：只比较同框架、同模型架构、同类基础设施内的替代做法。不需要更换框架或换硬件的方案不纳入强制比较。

### 判定规则

| 条件 | 结论 |
|------|------|
| #1 或 #2 FAIL | **否决方案** — 请用户重新提方案 |
| FAIL >= 2 条 | **否决方案** — 出报告退回，说明原因 |
| FAIL = 1 条（非 #1/#2） | **建议修改** — 修改后重走 Phase 2 |
| 全部 WARN <= 2 条 | **通过** — 进入 Phase 3，标注风险 |
| 仅 WARN >= 3 条但无 FAIL | **通过但标注风险** — 进入 Phase 3 |

### 输出

```
### Phase 2: 逻辑检查结果

  --- 7 项逻辑检查 ---
  [OK] 目标对齐       方案直接解决"降低 FID"目标
  [OK] 因果链合理     larger CFG -> more contrast -> lower FID
  [!]  竞品方案       已知可考虑 reduce EMA decay (同成本量级)
  [FAIL] 可执行性     需要 8xA100 但只有 4xV100

  -> 结论: 1 FAIL（可执行性），建议修改后重走 Phase 2
```
