## Phase 1: 意图澄清 + 成功标准

### 步骤

1. **复述用户需求**，确认理解正确
2. **界定范围**：
   - 做什么、不做什么
   - 约束条件（时间、资源、硬件、数据量）
   - 优先级（哪些必须做、哪些可裁剪）
3. **定义成功标准**：
   - 总体成功标准：怎么判断任务完成？用什么指标/现象？
   - 每个关键节点的验证方式（不要求此时就拆出子任务，只定义验收条件）
4. **识别用户未说但应该知道的事**：
   - 隐含风险（如"这个改动会影响其他正在跑的实验吗？"）
   - 被忽略的前提条件（如"需要先有 checkpoint-200.pth"）
   - 可选的决策点（如"两个方案都可以，需要你做选择"）

### 输出

```
## Plan: <任务标题>

### 目标
<一句话描述>

### 范围
- 做: <明确的范围>
- 不做: <明确不做的>
- 约束: <时间/资源/硬件>

### 成功标准
- <可验证的完成条件1>
- <可验证的完成条件2>

### 需要用户确认的点
- <在此阶段需要用户拍板的问题>
```

### 规则

- 必须让用户确认 Phase 1 的输出后，才能进入 Phase 2
- 如果需求本身模糊，先澄清再继续 — 不猜用户意图
- 成功标准必须**可验证**（"训练跑完"不是标准，"FID 低于 10"才是）
