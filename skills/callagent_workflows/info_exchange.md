# 流程② 与现存 agent 信息交换

**一句话**：与一个**已存在的会话**做双向信息交换（问答/数据/状态对齐）。
**适用**：跨会话状态同步、向值班会话求证、认知对齐、把结论落进对方上下文。
**不适用**：目标不存在（那是自动创建/任务派发 → longtask_manage）。

---

## 1. "现存"判定（严格）

```
判定条件：session_registry.json（<项目根>/session_registry.json）
中存在该键，即视为"现存"（有历史上下文）。
参考：mail.jsonl 历史 from/to 出现的会话名可辅助确认活跃度。
```
> 不满足时**不要**走本流程（自动创建的会话无上下文记忆，交换没意义）。

## 2. 设计交换协议（一次说清）

- **问什么/答什么**：约定格式（JSON/纯文本/指定字段）
- **时效**：X 轮内 / Y 分钟内；不回复=无信息
- **确认机制**：结论需确认 → `need_reply=true`（单对单可用，注入回信指引）；或信内"请回信确认"

## 3. 发信模板

```python
# 询问（要回执）
callagent(to="<现存会话>", message="[信息交换] 背景：…\n问题：…\n"
          "期望回复：{格式}。若无信息请回 '无'。请在 10 分钟内回复。",
          need_reply=True, reply_to=<对方来信 msg_id>  # 若是答复

# 通知（单向，无需回）
callagent(to="<现存会话>", message="[状态同步] …", need_reply=False)
```

## 4. 流程与防乒乓

```
① 确认目标现存（registry）
② 发问（含格式+时限）
③ 对方回信 → 主会话收到（新回合）
④ 校验：格式/字段 → 歧义则二次澄清（最多 2 轮）
⑤ 收尾：结论确认（回执）后结束；不得连环追问
```

| 异常 | 处理 |
|---|---|
| 对方不回 → 超时/dead | 判定"无信息"，标记通道不可用，换途径 |
| 答非所问 | 重问 1 次或降级处理（不纠缠） |
| 对方回信格式不符 | 二次澄清（限 1 次） |

**自检**：一问一答闭环；结论双方确认；未引发连环回信（msg 数 ≤ 2N）。
