# 流程③ 长程任务托管（主管 + 子 agent + 巡检纠偏）

**一句话**：主管设定长程任务 → 切分给各子 agent → 子 agent 每步回信 →
主管**定时唤醒自己**检查进度与**偏离**并纠偏 → 验收收尾。
**适用**：任务 >1 回合（>10min / 跨小时/天/重启），且可由主管分解为 N 个相对独立部分。

---

## 1. 任务定义（启动前一次性完成）

- 目标 / 验收标准 / 工期 / **子任务切分**（N 个相对独立部分）
- 每子任务：`job=xxx, part=i/N`、步骤清单、每步产出约定、回信协议

## 2. 子 agent 命名规范（自动创建时强制）

```
<主agent名>_subagent_<角色>_<时间戳>
例：my_task_subagent_exec_20260904_1700
· 角色由主管定义：exec / check / worker / analyzer ...
· 时间戳短格式（MMDD_HHMM 或全格式）；名称规则 ^[a-zA-Z0-9_\-.]+$，总长 ≤100（2026-09-10 补充：session 可另设展示标题 title，支持中文/空格/emoji，仅用于展示，寻址/文件名/邮件 to 一律仍用 ASCII name）
· 现存 agent（registry 有记录）不需要此命名，直接使用原名
```

## 3. 分配（fanout）

```python
callagent(to=["<主>_subagent_exec_<ts>", "<主>_subagent_check_<ts>"],
          message="[job=xxx part=i/N] {子任务书}\n"
                  "回信协议：每步完成后 callagent 回信 to=主管（reply_to=本信，"
                  "带 step=k/M + 结论 + 风险[无/有:…]）。完成后回 done(产出摘要)。",
          need_reply=False)
```
> 子 agent 默认 plan 模式无挂载 → 任务书**自包含**（数据随信附上/可访问路径）。

## 4. 子 agent 执行期

每步回信（step 递增 + 结论 + 风险标记）→ 主管收集（读 mail.jsonl/回信）。

## 5. 主管巡检协议（自调度 = 闭环心脏）

```python
callagent(to="<当前会话名>", delay_seconds=<巡检间隔>,
          message="[第 n/M 次巡检 job=xxx]\n"
                  "① 进度：收集各子 agent 最近回信，对照计划（落后/正常/超前/卡死）\n"
                  "② 偏离：对照验收表判断各子 agent 产出方向是否脱离目标\n"
                  "③ 处置：落后→催办；卡死→重发该 part/换人；偏离→发纠偏信（见 §6）\n"
                  "④ 全部接近完成→缩短间隔；全 done→汇总结论并终止巡检。",
          need_reply=False)
```

## 6. 形式化验收对照表（偏离检测判据）

| 验收项 | 形式化判据 | 通过标准 | 偏离动作 |
|---|---|---|---|
| 产出存在 | 回信含 done/产出摘要 或 数据可查 | 缺一即 FAIL | 重发/换人 |
| 方向一致 | 结论关键词 ∈ 任务目标术语集合（定义时列出） | 交集 ≥80% | 纠偏信 |
| 进度达标 | step 数 / 预计步数 ≥ 计划阈值（如 70%） | <70% 标记落后 | 催办/加资源 |
| 风险上报 | 回信显式含"风险：无/有：" | 未申报视为未发现 | 问询确认 |

> 主观项（方向一致）以**证据链**为准：引用子 agent 回信原文判定，不做印象评判。
> LLM 按表逐项判；表外的模糊偏差由 LLM 自行判断（不强制形式化）。

## 7. 纠偏信模板（巡检发现偏离时）

```python
callagent(to="<偏离的子agent>",
          message="[纠偏 job=xxx part=i] 你当前方向偏离目标：{引用证据}。
                  目标重述：…。红线：…。请确认收悉并调整。",
          need_reply=True)   # 单对单可用，要求回执确认
```

## 8. 收尾

- 全部 part done → 主管对照验收表逐项核对 → 汇总结论 → job 终态
- 停止巡检（显式终止）+ 归档（进度表/纠偏记录可审计）

## 9. 异常矩阵

| 异常 | 处理 |
|---|---|
| 子 agent dead | 重发该 part（job+step 断点续传）或改派 |
| 服务重启 | send/delivered 行持久 → postman 恢复投递（两阶段自动启动） |
| 子 agent 借频繁偏离 | 换更细任务书 / 更低复杂度子任务（降级策略） |
| 巡检自环不终止 | 循环协议自带 [第 n/M 次] + 显式终止条件 |

**自检**：所有 part 有逐 step 回信链；每次巡检有记录；偏离 ≤2 次内被纠正；产出对照验收表通过。
