# 流程① 定时唤醒任意 agent

**一句话**：到点让某个 agent（不一定是自己）醒来执行指定任务。系统唯一的"定时触发器"。
**适用**：巡检、心跳、定时汇报、到期提醒动作、让值班 worker 定时干活。

---

## 1. 设计唤醒协议（发信前想清 4 条）

| 要素 | 值 | 说明 |
|---|---|---|
| 唤醒谁 | `to=` 目标 | 任意会话（含自己）；未注册也会自动创建（→ 见 longtask_manage 命名规范） |
| 什么时候 | `delay_seconds=N` 或 `deliver_at=unix` | 相对/定点；到期 postman 投递（实测 0.6s 内） |
| 醒后干什么 | `message` | **自包含任务书**：背景+动作+完成标志+回信目标 |
| 需要回执 | `need_reply=false`（默认）| 单对单可 true；推荐信内显式指令（更可控） |

## 2. 发信模板

```python
# 唤醒自己（最常见）
callagent(to="<当前会话名>", delay_seconds=300,
          message="[心跳 job=xxx] 若任务已完成请回 done(summary)；若进行中发 next(进度)；"
                  "若失败发 err(原因)。收到即续发下一封心跳，任务终结后不再发。",
          need_reply=False)

# 唤醒他人
callagent(to="<目标会话>", delay_seconds=3600,
          message="[巡检到点] 请执行：{自包含动作}。完成后 callagent 回信 to=<本会话名>。",
          need_reply=False)
```

## 3. 投递语义（与"唤醒自己"的差异）

| 场景 | 行为 |
|---|---|
| 目标空闲 | 立即投递 → 目标新回合 |
| 目标处理中（_turn_active） | 跳过等待，空闲后续投（串行） |
| 目标未运行/未注册 | 自动创建并启动（两阶段投递）→ 就绪后投递 |
| 投递失败 | failed → 自动重投（≤2）→ dead（人工查） |

## 4. 循环协议（周期性唤醒 = 自驱动链）

- 头：`[第 N/M 次]`（防漂移）
- 终止条件：次数到 M / 条件满足 / 人工停 —— **必须显式写一条**
- 每轮处理完：需要继续 → 发下一封（delay=周期）；否则不再发

## 5. 异常与自检

| 异常 | 处理 |
|---|---|
| 循环不终止 | 协议没写终止条件 → 立即停止续发（最严重事故） |
| 心跳间隔 > 300s | 目标可能被 idle 回收 → 间隔调 <300s |
| need_reply=true 且信到别人 | 可能诱发回信 ping-pong → 通知型用 false |
| 醒来后上下文不完整 | 信内重申循环状态（"第 N/M 次，本轮做 X"） |

**自检**：mail.jsonl 有完整 send→delivered→done 链；终止后 24h 无新自调度信。
