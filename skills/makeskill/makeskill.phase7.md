## Phase 7: 结构化与简化

### ⚠️ 核心原则

> **拆分的目的不是让文件变小，而是让 LLM 在正确的时间点加载正确的内容，
> 在不需要的时候不浪费上下文。**

### 触发条件

| 触发方式 | 说明 |
|----------|------|
| **用户主动要求** | 用户选择结构化模式 |
| **大小阈值** | skill.md > 5KB 时自动建议 |
| **规范化附带** | 规范化时如果文件过大，一并建议 |

---

### 🧩 四类内容 + 判定标准

拆分前，将 skill.md 中每个内容块按以下 **4 类访问模式** 标记：

| 类别 | 标记 | 含义 | 去处 |
|------|------|------|------|
| **常驻** | `[ALWAYS]` | 整个执行过程都可能需要回查 | 留在精简后的 skill.md |
| **阶段** | `[PHASE:N]` | 仅在进入 Phase N 时需要 | 拆为 `<name>.phaseN.md` |
| **分支** | `[FORK:C]` | 仅在用户做出决策 C 后才需要 | 拆为 `<name>.<forkslug>.md` |
| **懒加载** | `[LAZY]` | 仅在特定事件/条件触发时需要 | 拆为 `<name>.<topic>.md` |

#### 判定细则

| 判断维度 | `[ALWAYS]` 常驻 | `[PHASE:N]` 阶段 | `[FORK:C]` 分支 | `[LAZY]` 懒加载 |
|----------|----------------|-----------------|----------------|----------------|
| **访问频率** | 多次回查 | 该阶段一次 | 决策后一次 | 偶发 |
| **体积影响** | 适中小于 2KB | 无限制 | 无限制 | 无限制 |
| **语义依赖** | 全局知识 | 阶段特有 | 分支特有 | 边缘/工具性 |
| **典型内容** | rules、导航图 | Phase 详细步骤 | 模式对比、分支示例 | 代码模板、FAQ |

---

### 📐 拆分后的 skill.md 结构（导航仪表盘）

精简后的 skill.md 应只包含：

```
1. YAML frontmatter          — [ALWAYS]
2. 概要（1-2 段）             — [ALWAYS]
3. 执行导航表 + 加载指令       — [ALWAYS] ← 核心新增
4. 关键硬规则（3-5 条最常用）   — [ALWAYS] ← 常驻，不拆出
5. 文件引用清单               — [ALWAYS]
```

### 📖 导航表设计规范

导航表是拆分后 skill.md 的灵魂，必须包含：

| 列 | 必填 | 说明 |
|----|------|------|
| **加载时机** | ✅ | 精确描述 LLM 何时应该加载该文件 |
| **指令** | ✅ | 显式的 `pythonrt 读取 skills/<name>/<filename>.md` 指令 |
| **说明** | ✅ | 该文件包含什么内容 |

**"加载时机"的写法规范：**

```
✅ 好: "进入 Phase 2 时"
✅ 好: "用户选择「新建」后"
✅ 好: "Phase 5 中需要生成代码模板时"

❌ 差: "按需读取"
❌ 差: "需要参考示例时"
❌ 差: "加载技能后参考"
```

**每条加载指令必须是 LLM 可以精确判断的条件。**

### 🛠️ 拆分执行流程

#### 步骤 1: 内容审计

逐段分析 skill.md 的每个内容块，标记其访问模式：

```markdown
---
YAML frontmatter → [ALWAYS]
---
## 概要            → [ALWAYS]
## 工作流程         → [ALWAYS]
## Phase 1 详情     → [PHASE:1]
## 三种模式详解      → [FORK:新建]
## 脚本模板         → [LAZY:需要代码模板时]
## 硬规则           → [ALWAYS]
## 边界条件         → [LAZY:遇到错误时]
```

#### 步骤 2: 分组合并

相同访问模式 + 相同触发条件的内容合并为一个子文件：

| 标记 | 合并规则 |
|------|---------|
| `[PHASE:1]`, `[PHASE:2]`... | 各一个文件 → `<name>.phaseN.md` |
| `[FORK:C]` 相同 C | 一个文件 → `<name>.<fork>.md` |
| `[LAZY]` 相近主题 | 一个文件 → `<name>.<topic>.md` |

#### 步骤 3: 生成导航树

在精简 skill.md 中生成「执行导航」表格，覆盖所有子文件。

#### 步骤 4: 执行拆分

```python
# pythonrt 备份 + 写入 + 校验 三合一（不用 shutil/cp/bash）
import os

name = '<name>'
base = f'skills/{name}'
src = os.path.join(base, 'skill.md')

# ① 备份（纯 open 二进制复制）
with open(src, 'rb') as fh:
    data = fh.read()
with open(src + '.bak', 'wb') as fh:
    fh.write(data)

# ② 写入精简版 skill.md（仅含 [ALWAYS] 内容 + 导航树）与各子文件
with open(src, 'w', encoding='utf-8') as fh:
    fh.write(精简版_skill_md)
for sub, content in 子文件.items():
    with open(os.path.join(base, sub), 'w', encoding='utf-8') as fh:
        fh.write(content)

# ③ 读回校验：导航表行数 == 子文件数，路径均存在
...（校验逻辑见 Phase 6）
```

#### 步骤 5: 验证

```
✅ 每个子文件有且仅有一个加载条件（导航表中一行对应一个 pythonrt 读取指令）
✅ 导航树覆盖所有子文件（无遗漏）
✅ 所有 pythonrt 读取指令均可执行（文件路径正确）
✅ [ALWAYS] 内容确实常驻在 skill.md 中
✅ 无 [ALWAYS] 内容被误拆出
```

---

### ✅ 验证清单

| 检查项 | 方法 |
|--------|------|
| 导航完整性 | 导航表的行数 == 子文件数 |
| 路径正确性 | 每个 pythonrt 读取路径的文件确实存在 |
| 常驻完整性 | skill.md 中无 `[PHASE:N]`/`[FORK:C]`/`[LAZY]` 内容 |
| 无重复 | 同一内容不在多个文件中出现 |
