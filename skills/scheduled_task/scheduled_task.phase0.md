## Phase 0 — 交互确认

> 📂 **加载时机**：进入 Phase 0 时加载
> **用途**：与用户自然语言对话，明确三个关键信息
>
> ⚠️ **前置条件**：已执行 Mode Pre-Check，当前模式已确定

---

### 步骤 0.0: 回顾当前模式

来自 Mode Pre-Check 的检测结果，当前模式为：

| 模式 | 对 Phase 0 的影响 |
|------|-------------------|
| 🔵 **plan** | 后续条件脚本存 `/tmp/`，Phase 2 仅 python 工具 |
| 🟢 **build** | 条件脚本存 `skills/scheduled_task/`，正常执行 |
| 🔥 **build-unsafe** | 同 build，Phase 2 可执行系统命令 |

---

### 步骤 0.1: 确认等待条件

向用户了解要等待的条件。支持以下类型（可组合）：

| 类型 | 示例 |
|------|------|
| ⏰ **绝对时间** | "明天早上 9:00"、"2026-07-25 18:00:00" |
| ⏳ **相对时间** | "30 分钟后"、"2 小时后" |
| 📊 **条件表达式** | "CPU 使用率 > 80%"、"文件 /tmp/ready.txt 存在" |
| 🗓️ **复合条件** | "周五 17:00 且系统负载 < 2.0" |

### 步骤 0.2: 确认待执行命令

> "条件满足后，你要执行什么操作？"

示例回复：
- "帮我运行备份脚本 backup.sh"
- "发送通知到钉钉群"
- "重启 nginx 服务"
- "打印系统状态报告"

### 步骤 0.3: 确认轮询间隔

询问用户："每多少秒检查一次条件？（默认 5 秒）"

> ⚠️ **Phase 0 输出**：将条件描述、待执行命令、轮询间隔、**当前模式** 四个信息传递给 Phase 1。
