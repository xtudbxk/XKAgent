## Phase 4: 输出结构化报告

### 核心问题

> **报告格式清晰易读，每个问题可追溯、可决策。**

---

### 报告格式

#### 问题卡片格式

每个问题用如下格式呈现：

```
❌ P0 L<行号>: <问题描述>
   类型: <检查类别>
   严重级别: P0/P1/P2
   详细说明: <为什么这是个问题>
   ─────────────
   <上下文代码片段>
```

#### 完整报告结构

```
## 📋 检查报告: <文件名/项目名>

总问题数: N
检查时间: <时间>
检查模式: <plan/build>

---

### 🔴 P0 — 运行时必然崩溃 (N 个)

❌ P0 L42: 未定义引用: 'np'
   类型: 逻辑检查 → 未定义引用
   说明: 在第 42 行使用了 'np'，但在任何作用域中都未找到定义
   ─────────────
   norms = np.linalg.norm(embeddings, axis=1)
   ^^
   💡 建议: 添加 import numpy as np

---

### 🟡 P1 — 可能导致错误或安全风险 (N 个)

⚠️ P1 L128: 裸 except
   类型: 逻辑检查 → 裸 except
   说明: bare except 会捕获包括 KeyboardInterrupt 在内的所有异常
   ─────────────
   try:
       process(data)
   except:
   ^^^^^^^
       pass
   💡 建议: 改为 except Exception:

---

### 🔵 P2 — 建议优化 (N 个)

ℹ️ P2 L5: 未使用导入: 'queue'
   类型: 导入检查 → 未使用导入
   说明: 第 5 行导入后未在代码中引用
   ─────────────
   import queue
   💡 建议: 移除未使用的导入
```

---

### 输出规则

1. **按严重级别分组**：P0 → P1 → P2
2. **每组内按行号升序**
3. **每个问题必须包含**：
   - 错误/警告标签 (❌/⚠️/ℹ️)
   - 严重级别 (P0/P1/P2)
   - 行号（如有）
   - 问题描述
   - 检查类型
   - 详细说明
   - 上下文代码片段（至少一行）
4. **可选字段**：建议修复方案（以 💡 标注）

### 无问题时的输出

```
## 📋 检查报告: <文件名>

   ✅ 未发现任何语法或逻辑问题。
```

---

### 后续操作建议

| 级别 | 建议操作 |
|------|---------|
| **P0 🔴** | 必须修复，否则程序会在对应路径崩溃 |
| **P1 🟡** | 建议修复，不修可能会在特定条件下出问题 |
| **P2 🔵** | 可选择修复，不影响运行时正确性 |
