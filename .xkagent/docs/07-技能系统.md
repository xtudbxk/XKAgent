# 07 · 技能系统

简体中文 | [English](07-skills.md)

---

Skill 是放在 Agent 内核之外的工作说明：它可以描述领域知识、操作步骤、检查清单和停止条件，让 XKAgent 在不修改主循环的前提下学习新的工作方式。Skill 本身是提示词扩展，不会自动注册 Python 工具，也不会绕过当前模式和路径权限。

## 技能放在哪里

每个技能占一个目录，入口文件固定为 `skill.md`。加载器只查看技能根目录的直接子目录，并按以下优先级查找：

```text
<workdir>/.xkagent/skills/<技能名>/skill.md   # 项目自定义，优先
<XKAgent代码根>/skills/<技能名>/skill.md      # 内置技能，兜底
```

目录名就是技能名。在项目目录下放置同名技能即可覆盖内置版本；`/skills` 仍只显示一次。删除自定义版本后，加载器会重新使用内置版本。这种方式既方便按项目定制，也不会直接改动 XKAgent 自带的技能。

## 写一个技能

`skill.md` 由 frontmatter 和正文组成。下面是一个可用的最小示例：

```markdown
---
name: release_check
version: 1.0.0
description: 发布前检查版本、测试与变更说明
category: workflow
triggers:
  - 发布检查
  - release
---

执行发布任务前：
1. 确认工作区状态。
2. 运行项目测试。
3. 检查版本号和变更说明。
4. 发现风险时先报告，不直接发布。
```

保存到 `.xkagent/skills/release_check/skill.md` 后，可先运行 `/validate release_check`。正文适合写目标、步骤、判断条件和风险提示；与其罗列函数，不如说明 Agent 在什么情况下应做什么。

### Frontmatter 约定

`/validate` 会检查四个必填字段：

- `name`：必须与目录名完全一致
- `version`：使用 `1.2.3` 形式的语义化版本
- `description`：简要说明技能解决什么问题
- `category`：只能是 `tool` 或 `workflow`

`triggers` 是可选列表，可放常见的中英文触发词。解析器只支持简单的 YAML 子集，包括 `key: value`、缩进列表和一级子键；不要依赖行内数组、锚点、复杂类型或深层嵌套。

## 技能怎样进入回合

普通消息开始时，系统会用技能正文以及 frontmatter 中的 `description`、`triggers` 做本地匹配，并把候选技能放进 Status。自动技能选择默认开启；选中后，技能正文会进入当前会话上下文。同一版本已经完整注入过时，后续回合会使用内容锚点，减少重复占用 token。

常用命令如下：

- `/skills`、`/showskills`：列出当前可加载的技能
- `/validate [names]`：校验全部技能或指定技能
- `/skill <name>`：读取技能并加入当前 Agent 的活动技能列表
- `/turnonskill`、`/skillson`：开启自动技能选择
- `/turnoffskill`、`/skillsoff`：关闭自动技能选择

`/skill` 与普通回合中的自动选择是两条独立路径；当前实现不会把 `/skill` 等同于“下一回合强制执行”。需要验证技能效果时，建议开启自动选择后发送一条真实任务，并观察界面显示的候选与最终选择。

## 修改后何时生效

技能支持热加载，无需重启进程。正文每次加载都会重新读取；frontmatter 按文件修改时间和大小缓存，文件变化后自动重新解析。新建或删除技能目录后，再执行 `/skills` 就能看到结果。

有几个实现边界值得留意：

- 加载技能不会自动执行格式校验，修改后应先运行 `/validate`
- `__init__.py` 不会被导入，目录中的代码也不会自动变成工具
- 加载器读取 `.xkagent/skills`，而搜索系统默认的 `skills` scope 指向 `<workdir>/skills`；自定义技能仍可通过 frontmatter 参与推荐，但正文未必进入该 scope
- 技能只影响提示与流程，实际读写能力仍由 `plan`、`build`、`build-unsafe` 和挂载配置决定
