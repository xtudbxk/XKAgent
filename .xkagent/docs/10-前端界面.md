# 10 · 前端界面（CLI / Web）

简体中文 | [English](10-frontends.md)

CLI 和 Web 是同一套 Agent Runtime 的两种入口。前者适合在本地终端中持续工作，后者提供浏览器聊天、多会话和文件操作；二者共用 `AgentManager`、命令系统，以及 `<workdir>/.xkagent/` 下的会话数据。

## 选择合适的入口

- 日常开发、快捷键输入和脚本式调用，优先使用 CLI。
- 需要浏览器聊天、移动端访问、会话侧边栏或文件上传时，使用 Web。
- 两端可以访问同一批 session，但同一 session 同时被多个进程打开时，只有持锁进程可以写入，其他实例会进入观察者状态。

## CLI：从终端开始

不指定 `--mode` 时默认进入 CLI：

```text
python -m codes --workdir <项目目录>
```

常见启动方式如下：

```text
python -m codes --workdir <项目目录> --session demo
python -m codes --workdir <项目目录> --resume
python -m codes --workdir <项目目录> --prompt "检查当前项目"
```

`--session` 指定会话名，`--resume` 恢复最近会话，`--prompt` 只完成一次请求便退出。不指定会话时，程序会优先选择最近使用的 session；没有历史会话才创建时间戳名称。

交互模式提供一套无额外依赖的行编辑体验：

- `↑` / `↓` 浏览输入历史，方向键、Home、End 和 Delete 编辑当前行。
- 行尾输入 `\` 可继续下一行；Tab 在 `plan`、`build`、`build-unsafe` 间循环，并保留尚未提交的文字。
- Ctrl+N / Ctrl+P 切换正在运行的 session；切换焦点不会停止原 session 的回合。
- Ctrl+C 中断当前回合，Ctrl+E 使用 `$EDITOR` 编辑缓冲区，Ctrl+L 清屏，Ctrl+W 删除前一个词。
- `@<path>` 将文件内容带入请求；`!<command>` 直接在宿主机执行 shell，不经过 `pythonrt` 沙箱。

raw 终端编辑依赖 `termios`，主要面向类 Unix TTY。标准输入不是 TTY 时，CLI 会退化为逐行读取，不提供上述快捷编辑能力。

## Web：从浏览器工作

Web 需要 FastAPI 和 Uvicorn，可通过统一入口启动：

```text
python -m codes --mode web --workdir <项目目录>
```

默认地址是 `http://127.0.0.1:7860`。可以用 `--port` 修改端口，也可以使用固定为 Web 模式的兼容入口：

```text
python -m codes --mode web --workdir <项目目录> --port 9090
python -m codes.web_main --workdir <项目目录>
```

服务启动后不会自动打开浏览器。它会选择最近的 session 作为默认会话，并在后台预热对应 Agent，以减少首次请求等待。

### 会话与实时状态

侧边栏可以创建、切换、停止和 fork session。停止只结束 Agent 线程，不删除 SQLite 中的消息；再次切回时会重新启动并恢复会话。切换焦点也不会打断其他 session 正在执行的回合。

页面首次读取最近 50 条消息，并可继续向前分页；新消息和 Agent 事件通过 WebSocket 流式显示。界面会同步展示 LLM、工具执行、锁、崩溃与恢复状态。同一 session 被其他进程持锁时，当前实例只能观察，不能提交会改变状态的操作。

模型回复在流式阶段以纯文本持续追加，回合结束后统一渲染 Markdown 和文件路径链接。工具调用、执行进度、结果、Thinking 与 Summary 分别使用可折叠区域展示，刷新或切换 session 后会从历史记录恢复一致的视图。工具栏中的 **Clear View** 只清空当前浏览器视图，不删除 session 数据；重新进入该 session 仍会加载历史消息。

模式按钮和 Skill 自动选择开关针对当前 session；模型可以设置到当前或所有已启动 session。slash 命令与 CLI 使用同一注册表。Web 无法进行终端式确认，危险挂载需要按提示显式添加 `--force`。

### 文件浏览与上传

文件页只允许浏览、打开和下载以下根目录：

- 当前 workdir；
- `permission.txt` 中的静态挂载；
- 当前 session 保存的动态挂载。

后端会先做 `realpath` 归一化，再检查目标是否位于允许根内，因此指向根外的符号链接不会绕过限制。

上传文件写入 `<workdir>/.xkagent/files/`。服务只保留文件名的 basename，重名时增加时间戳，并按 1 MB 分块落盘。图片可以继续作为会话附件使用，其他文件可通过返回路径引用。当前上传接口没有总大小上限，需要自行关注磁盘空间。

## 认证与部署边界

Web 认证默认关闭，只有传入 `--password` 才启用；用户名默认为 `admin`：

```text
python -m codes --mode web --workdir <项目目录> --user admin --password <密码>
```

登录成功后，服务在进程内保存 token，并写入 session Cookie。关闭浏览器后 Cookie 失效，进程重启后旧 token 也不再有效。这套机制只是一层单账号访问保护，不是多用户权限系统，也不提供 TLS；所有登录者共享同一工作目录和 Agent 能力。

默认监听 `127.0.0.1` 只是缩小可访问范围，并不等同于认证。同机用户或进程仍可能访问未启用认证的服务。建议：

- 保留本机监听，不进行端口映射、内网穿透或公网暴露；
- 在受控内网共享前启用强密码，并遵循组织的访问控制要求；
- 将上传、下载、slash 命令和 `!shell` 都视为高权限入口；
- 不在聊天、命令历史或上传文件中保存密钥；
- 仅在可信环境使用 `build-unsafe` 和 `!shell`，二者不受常规沙箱保护。

最后还需注意：CLI 与 Web 共用 `.xkagent/history.txt` 输入历史，但 `/cmds` 读取的是当前 session 数据库中的命令记录；`/exit` 在 CLI 中退出交互循环，在 Web 中请求关闭服务器。
