# 05 · 沙箱与工具执行

简体中文 | [English](05-sandbox-and-tools.md)

XKAgent 采用 **code over tools**：模型不需要为读取文件、转换数据或调用库逐个选择专用工具，而是用 `pythonrt` 编写一段 Python，把相关步骤组合起来执行。少量辅助工具负责搜索、持久化和流程控制，通用计算仍集中在一个运行时中。

## 工具面保持精简

主 Agent 当前向模型提供 6 个工具：

- `pythonrt`：执行 Python，是文件操作、数据处理和多步逻辑的主要入口。
- `searchskill`：当前建议 Skill 不合适时，继续检索技能库。
- `searchinfo`：在指定且已授权的目录中搜索文件片段。
- `summary`：把值得跨会话保留的信息写入 `.xkagent/docs/<session>/`，成功后结束本轮。
- `exit`：遇到死循环、不可恢复错误或无法完成的任务时结束本轮。
- `agent`：在独立子进程中运行一个短期子 Agent 循环。

`agent` 复用同一套 Provider、模型和沙箱权限，并通过独立上下文完成委派任务；工具筛选、嵌套开关和返回格式见 [06 · Agent 引擎](06-Agent引擎.md)。

用户输入的 `!command` 是显式 shell 通道，不属于 LLM 工具集，也不经过 `pythonrt` 的 profile。它由用户主动触发，风险边界与模型工具调用不同。

## `pythonrt` 如何执行

模型通常应把一组相关操作放进同一段代码：读取必要文件、完成处理、验证结果，再通过 `print` 返回简洁摘要。这样既减少模型与工具之间的往返，也让路径和导入检查集中在一个执行边界。

`code_or_filepath` 可以是代码文本，也可以是一个已存在的 `.py` 文件路径。传入的 `workdir` 只控制 worker 的当前目录和相对路径基准，不能扩大授权范围；访问根始终由 Agent workdir、`permission.txt` 和动态挂载共同决定。

每次调用都会启动独立 Python worker。参数通过 stdin 以 JSON 传入，结果通过 `__SANDBOX_RESULT__` 标记返回；stdout/stderr 由读线程持续读取，并可转成工具进度事件。超时或中断时父进程会 kill 并回收 worker，通常返回 124（超时）或 130（用户中断）。已经完成的文件写入、数据库提交或网络请求不会因此回滚。

## 三种模式，三档信任

```text
plan         受限 Python；workdir 和挂载只读，/tmp 可写
build        受限 Python；workdir 可写，ro/rw 挂载可写，ro 挂载只读
build-unsafe 接近宿主 Python；允许任意 import、路径、网络和 subprocess
```

`plan` 与 `build` 使用同一套轻量沙箱，只在写权限上不同。两者默认允许项目适配过的网络栈和 SQLite；安装 dulwich 后也可使用内置 Git 路径。网络目标没有主机或 IP 白名单，因此“受限”不等于离线。

`build-unsafe` 会跳过常规受限执行，适合确实需要完整测试链、第三方 C 扩展或 subprocess 的任务。它不是小幅放宽的 `build`，而是明显降低安全级别；进入前应先提交 Git 或备份工作区。

## 路径权限如何确定

受限模式从三处合并访问根：

1. Agent workdir：`plan` 只读，`build` 可写。
2. `permission.txt`：`ro` 始终只读；`ro/rw` 在 `plan` 只读、在 `build` 可写。
3. `/mount`：按同样规则加入当前 session 的动态挂载。

`/tmp` 始终可写。动态挂载本身会保存到 session 数据库并在重启后恢复；`/mount save` 是把它们同步写入 `permission.txt`，不是动态挂载持久化的必要条件。

沙箱先将路径转换为 `realpath`，再按最长匹配根决定权限。这样可以阻止常规 `..` 和符号链接越界，也允许更具体的只读子目录覆盖可写父目录。`<workdir>/.xkagent` 保存配置、密钥、历史和状态，在所有模式下都意图保持只读；受限模式保护较完整，`build-unsafe` 只有部分 Python 写入口包装，不能视为不可绕过。

## 轻量沙箱的边界

`codes/sandbox.py` 使用标准库实现多层软限制：移除 `exec`、`eval`、`compile` 等内建入口，包装常见文件与 `os` 路径操作，限制危险模块和第三方库，并在支持的平台设置 CPU、内存、文件大小和打开文件数上限。SQLite、网络栈、dulwich 等通过扩展注册和入口 patch 定向放行。

这些措施的目标是降低 LLM 误操作，例如写错目录、误删项目外文件或意外启动命令。它不是容器、虚拟机或 WASM 隔离，也不防蓄意逃逸、恶意依赖和内核级攻击。第三方 C 扩展可能绕过 Python 层包装，未经审查的库应只在可信代码和 `build-unsafe` 中使用。

Windows 等不支持 `resource`/`RLIMIT_*` 的平台会跳过相应资源上限；父进程超时 kill 仍然有效，但内存和文件大小未必有硬限制。受限脚本不能自行通过 `subprocess` 执行命令，不过主程序仍会为隔离而启动 `pythonrt` 或 `agent` worker。

## 写入不是事务

`pythonrt` 直接修改真实工作区，没有写前快照、逐文件事务或失败自动回滚。Agent 可以参考当前会话记录、备份文件和 diff 尝试反向修改，但结果仍需人工检查。worker 在脚本执行中途报错或被 kill 时，也可能留下部分修改。

当前已实现的是三种 profile、路径与导入限制、worker 隔离、进度透传、中断和资源限制降级。自动快照、事务式回滚、容器级隔离以及网络目的地策略都没有实现，属于未来可增强方向，不能按现有沙箱能力推断。
