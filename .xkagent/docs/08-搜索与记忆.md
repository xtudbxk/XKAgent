# 08 · 搜索与记忆

简体中文 | [English](08-search-and-memory.md)

---

XKAgent 已经实现了本地搜索、会话历史和每回合 Status 注入，也能把总结保存成可检索文档；但这几项能力还不是完整的长期 Memory。理解它们各自负责什么，可以避免把“存过”误认为“以后一定会想起”。

## 四个概念，各自解决什么

- **搜索**从指定目录查找与当前问题相关的短片段，结果可能命中，也可能没有命中
- **会话历史**保存在当前 session 的 SQLite 数据库中，恢复 session 时可继续作为对话上下文
- **Status**是每条普通消息前临时生成的状态前缀，让模型看到当前时间、模式、路径权限、候选技能和推荐信息
- **长期 Memory**仍在规划中；目前没有事实实体库、冲突消解、遗忘策略或用户画像管理

因此，Status 不是一份独立记忆库，搜索结果也不是可靠召回保证。现有能力更准确地说，是未来 Memory 可以利用的状态与检索底座。

## 每个普通回合发生什么

Agent 收到普通消息后，会先按消息内容检索候选技能和相关信息，再构造 Status：

```text
时间
系统模式（plan / build / build-unsafe）
项目根、/tmp、.xkagent 和挂载路径的权限摘要
建议技能
推荐信息
正文
```

这段前缀会和正文一起写入当前会话历史并发送给模型。CLI 和 Web 会把状态单独展示，回看用户消息时只保留易读正文。

推荐信息默认搜索文档、其他会话历史和日志；`skills` 结果由技能推荐通道单独处理，当前 session 的历史也会被排除，因为它已经在当前上下文中。thinking、tool 结果和技能注入辅助消息会被过滤。每个文件最多保留两段，最终只注入少量路径和短片段；检索失败会静默降级，不会阻断对话。

## 默认搜索范围

所有相对路径都以 `<workdir>` 为基准：

```text
skills   → <workdir>/skills
docs     → <workdir>/.xkagent/docs
historys → <workdir>/.xkagent/historys
logs     → <workdir>/.xkagent/logs
```

`codes` 默认不参与搜索，可按需添加。`historys` 是当前代码使用的固定拼写。另一个容易混淆的地方是：技能加载器读取 `<workdir>/.xkagent/skills` 和内置 `skills`，而搜索系统的默认 `skills` scope 指向 `<workdir>/skills`。项目技能仍可根据 frontmatter 推荐，但正文不一定进入这个搜索范围。

### 调整范围

`/info` 会显示全局配置、当前 session 配置及合并结果：

```text
/info
/info add docs/design docs
/info add codes codes
/info deny secrets
/info remove codes
/info clear
```

这些命令默认修改当前 session 的 `search_state`。加 `--global` 后会改写 `.xkagent/search_ranges.txt`，供所有 session 使用：

```text
/info add --global shared/docs docs
/info deny --global private
```

`deny` 按路径前缀排除目标及其子树。当前跨 scope 自动推荐没有把 session 参数完整传给每次内容收集，因此依赖稳定的自动推荐范围时，优先使用全局配置；session 配置仍会显示和保存，但部分场景可能没有完整生效。

## 检索方式

默认主通道是本地 ngram，适合中文、关键词和短语，不需要模型服务。语义型内容先做 ngram 匹配，无结果时用 grep 兜底；配置、日志和代码符号等精确内容优先使用 grep。超过 1 MB 的语义型文件不会做结构化提取。

Embedding 是可选补充，默认关闭。启动前设置以下环境变量即可启用：

```text
XKAGENT_EMBEDDING=1
```

`true` 和 `yes` 也会被识别。启用后，系统会异步预热本地 ONNX 模型，并把向量结果合并到 ngram 结果中；缺少 FAISS、ONNX Runtime、Transformers 或 NumPy 时仍会退回 ngram。

使用 `/updateembedding` 可全量重建 `.xkagent/search_index/<scope>.db`，别名是 `/updateskillembedding`。该命令会实际执行向量编码，即使 embedding 开关未启用。索引目前不会随文件变化自动增量更新。

> 本地模型不完整时，首次向量编码会尝试从项目配置的外部 SharePoint 地址下载【非官方】模型包。内网环境中请先确认软件来源和网络策略；不需要向量检索时保持默认关闭。

## 会话历史、Compact 与 Summary

每个 session 的消息保存在 `.xkagent/historys/<session>.db`。普通恢复会重新载入有效历史；这与跨 session 的检索不同：前者是当前对话上下文，后者只是从其他数据库中寻找相关片段。

上下文过长时可以运行 `/compact`。系统通过一次专用模型回合生成总结，成功后：

- 在数据库中写入 `compact` 标记，旧消息仍保留
- 用总结替换后续发送给模型的内存上下文
- 写入 `.xkagent/docs/<session>/<时间戳>_compact.md`

压缩不是删除历史，也不是清空 session；生成失败或被中断时不会执行收尾。

Agent 还可以调用 `summary` 工具，把重要决策、约定、外部事实或关键流程写入：

```text
.xkagent/docs/<session>/<时间戳>_summary.md
```

成功调用会立即结束当前回合。Summary 和 Compact 文档都进入 `docs` scope，之后可能被检索到，但不会被无条件注入，也不保证未来一定命中。它们是可检索的持久化资料，不是已经实现的长期 Memory。
