# 01 · 入口与启动

简体中文 | [English](01-entry-and-startup.md)

本篇从安装开始，说明如何进入 CLI 或 Web，以及 `--workdir`、会话参数和启动目录究竟会影响什么。

## 先安装需要的能力

XKAgent 的 CLI 和 LLM 调用层只要求 Python 与 `requests`：

```bash
python -m pip install requests
```

如需 Web、语义搜索和沙箱内 Git，可一次安装完整依赖：

```bash
python -m pip install -r requirements.txt
```

这些依赖按能力分组，缺少可选组不会阻止核心 CLI 启动：

- `faiss-cpu`、`onnxruntime`、`transformers`、`numpy` 用于 Skill 语义搜索；不完整时会降级为 ngram/关键词匹配。
- `fastapi`、`uvicorn` 提供 Web 界面。
- `dulwich` 提供 `pythonrt` 中的 Git 扩展。
- `pythonrt` 已随源码提供，本身只使用标准库。

启动时会显示核心、语义搜索和 Web 组件的可用状态；当前检查不会单独列出 `dulwich`。

## 启动 CLI

在仓库根目录运行：

```bash
python -m codes --workdir /path/to/project
```

建议明确传入 `--workdir`，让项目范围和 `.xkagent` 运行数据落点一目了然。常见的会话用法如下：

```bash
python -m codes --workdir /path/to/project --session demo
python -m codes --workdir /path/to/project --resume
python -m codes --workdir /path/to/project --prompt "解释这个仓库"
```

未指定会话时，XKAgent 会优先打开最近使用的会话；还没有会话时则创建时间戳会话。`--resume` 要求已有会话，`--prompt` 会完成一轮请求后退出。

## 启动 Web

统一入口通过 `--mode web` 切换到 Web：

```bash
python -m codes --workdir /path/to/project --mode web
python -m codes --workdir /path/to/project --mode web --host 127.0.0.1 --port 7860
python -m codes --workdir /path/to/project --mode web --user admin --password "your-password"
```

默认监听 `127.0.0.1:7860`，默认用户名为 `admin`。只有设置 `--password` 后才会启用认证。

也可以使用专用入口：

```bash
python -m codes.web_main --workdir /path/to/project
```

`codes.web_main` 复用同一套参数和启动流程，但始终选择 Web；即使传入 `--mode repl` 也不会进入 CLI。

## 参数速查

- `--mode {repl,web}`：运行模式，默认 `repl`。
- `--workdir PATH`：项目范围及运行数据的基准目录。
- `-s, --session NAME`：选择 CLI 会话。
- `--resume`：恢复已有会话；未指定名称时选择最近会话。
- `-p, --prompt TEXT`：发送一轮 CLI 输入后退出。
- `--host HOST`、`--port PORT`：Web 监听地址和端口，默认 `127.0.0.1:7860`。
- `--user USER`、`--password PASSWORD`：Web 登录凭据；用户名默认 `admin`。

入口使用 `argparse.parse_args()` 严格解析参数，位置参数、未知参数或缺值都会直接报错。因此 `./run.sh /some/path` 不是合法的 workdir 写法，必须使用 `--workdir /some/path`。

## `run.sh` 如何处理路径

Linux/macOS 还可以使用：

```bash
./run.sh --workdir /path/to/project
./run.sh --workdir /path/to/project --mode web --port 9090
```

`run.sh` 会定位仓库目录，但不会切换调用方的当前目录；它直接以绝对路径运行 `codes/main.py` 并原样透传参数。依赖需要提前自行安装（核心只需 `requests`，可选组件见 `requirements.txt`），脚本不再自动安装。

脚本既不修改 cwd，也不设置 `PYTHONPATH`。Python 入口会根据自身位置把项目根加入 `sys.path`，因此代码导入不依赖从哪里调用脚本。相应地：

- `--workdir` 中的 `~` 会在 Python 入口展开。
- 相对 `--workdir` 以启动进程时的 cwd 为基准，而不是以 `run.sh` 所在目录为基准。

入口会先确定 workdir，再导入日志、历史等模块，确保后续创建的 `.xkagent` 路径都基于正确目录。具体目录结构见[配置管理](02-配置管理.md)和[基础设施](03-基础设施.md)。

## 从源码继续阅读

统一参数和模式调度位于 `codes/main.py`；`codes/__main__.py` 与 `codes/web_main.py` 分别是包入口和 Web 专用委托层。Shell 启动与依赖分组则可直接查看 `run.sh` 和 `requirements.txt`。
