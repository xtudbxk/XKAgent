# 03 · 基础设施（存储、锁、日志）

简体中文 | [English](03-infrastructure.md)

会话数据存在哪里、同名会话被占用时会发生什么、日志又写到了哪里？本篇集中说明这些日常使用不必关注、备份和排障时却很重要的基础机制。

## 运行数据放在哪里

XKAgent 把运行数据收拢在 `<workdir>/.xkagent/`。根据启用的功能，常见结构如下：

```text
<workdir>/.xkagent/
├── historys/
│   ├── <session>.msgz          # 单文件会话存储（zlib 压缩 JSON）
│   └── <session>.lockdir/      # 单写者 lease（owner.json）
├── state/
│   └── <session>.json          # 会话级 KV（状态板）
├── logs/
│   └── <启动时间>.log
├── docs/<session>/  # summary/compact 运行记忆
├── skills/
├── permission.txt
└── search_ranges.txt
```

会话锁（lockdir）和部分配置文件只在相关功能启用时出现；如目录中残留旧的 `*.db` 文件，它们仅作只读历史保留。当仓库根是 workdir 时，项目文档与运行记忆共用 `.xkagent/docs/`；每个会话的运行记忆仍位于独立子目录。

## 一个会话，一份 msgz 存储

每个 session 对应 `historys/<session>.msgz`——一个 zlib 压缩的 JSON 单文件，包含消息与各类会话状态（当前 Provider 与模型、token 统计、动态挂载、搜索范围、图片等）。会话名最多 100 个字符，只能包含字母、数字、下划线、连字符和点。

存储模型：

- **内存主数据**：消息与状态常驻内存，写入先在内存完成、立即返回；存储 I/O 故障不会让对话写入失败。
- **定时同步**：默认每 30 秒把内存快照原子落盘（先写临时文件，再 `os.replace` 替换），任意时刻磁盘上的文件都是完整一致的版本。
- **单文件搬运**：备份、复制与迁移都只需处理一个 `.msgz` 文件，没有 `-wal`/`-shm` 之类的 sidecar。
- **历史兼容**：旧的 `*.db` 文件不会自动删除，仅作只读历史保留；`codes/msgz_migrate.py` 可将 SQLite 会话一次性迁移为 `.msgz`。

斜杠命令和 `!` 命令会以 `role='command'` 写入历史，结果最多保留 4000 个字符。入库前会尝试遮盖常见的 token、key、secret、password、authorization 和 bearer 值。这只是基础兜底，不能保证识别所有凭据格式，因此命令中仍应避免携带不必要的敏感信息。

## 会话文件与备份

会话管理围绕单文件存储进行：

- 新建会话会初始化一份空的 `.msgz` 存储与 Agent 状态；首次落盘时创建文件。
- fork 会先把源会话落盘，再复制其 `.msgz` 作为新会话的起点（也支持按消息截断复制）。
- rename 会重命名对应的 `.msgz` 文件，并同步更新会话注册表。
- delete 会移除该会话的 `.msgz` 与 `.lockdir`（旧 `.db` 保留为只读历史）。
- sync 会强制把内存中的最新状态落盘（等价旧版 WAL checkpoint 的语义）。

写盘是“临时文件 + 原子替换”，因此磁盘上的 `.msgz` 任意时刻都是完整一致的版本；运行中直接复制也能得到有效快照（可能略旧）。若需要绝对新鲜的数据，可先执行 `/session sync` 或停止相关进程再复制。

## mkdir-lease：跨进程的单写者锁

XKAgent 没有使用 `flock`，而是通过原子创建目录来争抢会话写锁：

```text
historys/<session>.lockdir/owner.json
```

`owner.json` 记录进程实例 ID、PID、线程 ID、主机名、持有者和加锁时间。`mkdir` 在 NFS 服务端也是原子操作，因此多个客户端同时竞争时只有一个能够成功。

获得锁后，daemon 心跳线程每 10 秒刷新 `owner.json` 的 mtime；连续超过 35 秒没有刷新，锁才被视为 stale。接管者会先把旧 lockdir 原子重命名到临时目录，再创建新的 lockdir、写入自己的 owner 信息并启动心跳，最后清理旧目录。若 `owner.json` 尚未创建，stale 判断会暂时改看 lockdir 自身的 mtime。

同一进程也可能留下已退出线程的锁。恢复逻辑确认原持有线程已经死亡后，会停止旧心跳、移除残留并重新尝试加锁。

## 会话被占用时：观察者模式

另一个进程打开正在使用的同名会话时，不会直接崩溃，而会进入观察者模式。界面会显示占用状态和能够读取到的持有者信息；LLM 输入、存储写入及写类命令会被拒绝，避免绕过单写者约束。

观察者在空闲轮询时会继续尝试获取锁。原持有者正常退出，或锁因心跳停止而可以接管后，观察者会自动升级为持有者。

不要手工删除一个仍在正常续租的 `.lockdir`，否则可能破坏单写者保证。35 秒是崩溃恢复阈值，不是会话运行时限；健康进程会每 10 秒持续续租。

## 日志与轮转

日志模块首次导入时，会为当前进程创建：

```text
<workdir>/.xkagent/logs/YYYY-MM-DD_HH-MM-SS.log
```

每行包含时间（精确到毫秒）、级别、模块、函数、行号和消息。文件记录 `DEBUG` 及以上级别，控制台初始显示 `INFO` 及以上；进入 CLI 后，控制台阈值会调整为 `ERROR`，避免普通运行日志打断输入。

单个文件达到约 100 MB 后按 `.1`、`.2` 继续轮转，最多保留 7 份编号备份。这里的 7 指备份数量，不是天数。实现基于标准库 `logging.FileHandler`，日志同步写入，不依赖第三方日志库。

运行 `/logfile` 可以查看本进程的日志路径和最后 60 行，通常足以定位最近一次错误。

## 从源码继续阅读

`codes/history_msgz.py` 实现单文件存储（内存主数据、定时同步、原子落盘），`codes/history.py` 提供会话级 API 与文件操作，`codes/lock.py` 实现 mkdir-lease、心跳与 stale 接管，`codes/_log.py` 配置日志和轮转，`codes/msgz_migrate.py` 提供 SQLite 迁移；观察者模式及自动升级位于 `codes/agent.py`。
